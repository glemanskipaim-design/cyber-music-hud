   Enquanto a thread de captura espera `ActivateAudioInterfaceAsync`,
   `ActivateHandler::Wait` só olha `done_`, não `stopEvent_`. `Hud::Show`
   (música nova) e `Hud::Hide` (via Tick) chamam `AudioCapture::Stop()` ->
   `join()` na thread de UI. Se a ativação demorar, a UI congela até
   `kActivateTimeoutMs`. Correção: esperar os dois eventos.
   ```cpp
   ComPtr<IAudioClient> Wait(HANDLE stop, DWORD timeoutMs) {
     const HANDLE waits[] = {done_, stop};

     return client_;
   }
   ```
   Repasse `stopEvent_` por OpenProcessLoopback e, em Run, não caia para o
   loopback do sistema se o stop já foi sinalizado.
